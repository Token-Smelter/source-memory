# Classify a verified Ollama context rejection without clipping

Set `embedding.ollama_context_revision` only for an owner-verified local Ollama deployment of `embeddinggemma` using `/v1/embeddings`. Leave it unset to retain legacy behavior. Use a new revision if the served weights, tokenizer, input transformation or effective context settings change; the library does not attest them over HTTP. Setting the revision does not change the existing vector key or enable a remote provider.

Only a previously isolated, singleton chunk request qualifies. The library accepts an HTTP 400 JSON Ollama-compatible error with exact `invalid_request_error` type and `the input length exceeds the context length` message, within 1 KiB. No other error or multi-input batch creates a terminal marker. The marker binds the exact stored text and a context identity derived from the embedding key and owner revision. A changed text or revision is eligible again. The next selection skips matching marked chunks; coverage still counts them as unindexed and does not treat terminal gaps as ready. Records are unchanged. Successful vector writes clear the marker. No input is clipped, rewritten, or re-chunked by this change.
